## What this is for

Ruling D53 §2 (5) says nothing that happens inside the recompute may change a run's status. The review of #208 found two ways it does:
- a recompute sample whose call raises makes the whole run raise;
- a watchdog cut, or a pre-start refusal, at the recompute ends the run `blocked`.

This command fixes both:
- `run_recompute` records a failed sample and runs the next one;
- a node can be marked `advisory: true`. When its work raises, or the watchdog cuts or refuses it, the run stores the node's skip output and goes on. The recompute is the only node marked.

It also carries the advisor's ruling on the ident question: `_recompute_ident` no longer drops the words "in parallel". So the recorded T4-24 answer becomes a recorded false flag.

The review is `docs/reviews/2026-10-21-review-208-d53-phase1.md`, §2 (the two defects) and §3 (the ident ruling). The command is `.orchestration/commands/ARCH-20261021-124.json`.
